## Evaluation Run

- **Date:** 2026-10-01
- **Data:** 40,320 samples (7 days × 4 motors × 1 sample/min), generated by the
  deterministic simulator (seed 42)
- **Models trained:** Baseline (GradientBoosting per motor), Anomaly
  (IsolationForest per motor), Fault Classifier (RandomForest)
- **Reproduce:**
  ```
  .\.venv\Scripts\python.exe -m backend.app.simulator.simulator   # generate data
  .\.venv\Scripts\python.exe -m backend.app.ai.train              # train models
  .\.venv\Scripts\python.exe -m backend.tests.test_evaluation     # evaluate
  ```

## Known Limitations

1. Simulated data only — real sensor integration (Modbus/MQTT sources are stubs)
   needed for production
2. False-alarm rate on the raw anomaly score is 7.6 % of normal samples; the
   alert gate (score ≥ 0.5 **and** classifier ≠ normal **and** cross-asset not
   suppressing) is what keeps production alerts clean
3. Classifier is evaluated on the same 7-day simulated corpus it was trained
   on (per-class held-out windows) — real-world generalisation unproven
4. `imbalance` is a supported injected fault type but has no training samples,
   so the classifier never predicts it (it maps to vibration-based classes)
5. No authentication/authorization on API; SQLite only suitable for single node
6. Faults injected live take ~60 s to reach full ramp before detection
